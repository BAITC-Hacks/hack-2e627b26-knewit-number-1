# Контракт API ekt.kz

Дата проверки: 2026-09-23  
Проверка выполнена авторизованными запросами с Basic Auth. Секреты в этот файл
не записываются.

## 1. Каталог

Базовый адрес: `https://ekt.kz/api`.

### Список товаров

```http
GET /products
GET /products?page={page}&per_page={per_page}
```

Подтверждённый ответ:

```json
{
  "page": 1,
  "per_page": 20,
  "count": 20,
  "items": [
    {
      "id": 45357,
      "name": "...",
      "article": "...",
      "price": 1810,
      "image": "https://...",
      "url": "https://ekt.kz/catalog/.../",
      "url_api_detail": "https://ekt.kz/api/products/detail?id=45357",
      "offers": []
    }
  ]
}
```

Подтверждено:

- первая страница — `page=1`;
- стандартный размер — `per_page=20`;
- `per_page=100` принят API;
- `count` — количество элементов в текущем ответе, а не общее количество;
- `page=0` возвращает данные первой страницы и нормализуется в ответе к `page=1`;
- `page=999` возвращает набор первой страницы, но оставляет `page=999` в метаданных;
- отдельного `total`, `last_page`, `has_next` или иного признака конца не найдено;
- пустой ответ как признак конца не подтверждён.

Следствие для синхронизации: нельзя останавливаться только по номеру страницы
или `count`. Нужно прекращать обход при повторении набора ID либо после отдельного
согласования правила с партнёром. Для локального индекса следует дедуплицировать
товары по `id`.

### Детальная карточка

```http
GET /products/detail?id={id}
```

Подтверждённый набор полей detail для `id=515291`:

```json
{
  "id": 515291,
  "name": "...",
  "article": "...",
  "description": "...",
  "price": 64920,
  "quantity": 23,
  "stores": [
    {"id": 3, "name": "Шымкент (ул.Байдукова)", "quantity": 2}
  ],
  "image": "https://...",
  "url": "https://ekt.kz/catalog/.../",
  "offers": [],
  "properties": {"...": "..."}
}
```

Поля `properties` динамические и зависят от категории. Поля сертификата,
инструкции или документа в detail-ответе не обнаружено.

## 2. `offers`

За первые 1000 товаров (`10` страниц по `per_page=100`) непустых `offers` не
обнаружено. Схема элемента `offers` и идентификатор варианта не подтверждены.

До получения примера от партнёра:

- не извлекать из `offers` предполагаемые поля;
- не выбирать и не добавлять вариант автоматически;
- считать поддержанным только `offers: []`.

## 3. Остатки и склады

В detail присутствуют `quantity` и `stores[].quantity`. В проверенной карточке
`quantity=23` совпал с суммой складских остатков.

Это не является подтверждением бизнес-семантики. В ответе есть служебные склады,
в том числе `Брак`, `Маркетинг MEGALIGHT`, `перемещение`, `Восстановленный
продукт`, `Образцы Отдел Закупа`, `Витрина ТЗ`.

Не подтверждены:

- allowlist продающих складов;
- правила резервов и доступности по городу;
- связь общего `quantity` с реально доступным к заказу количеством;
- единица продажи, минимальная партия, шаг и кратность.

Пока партнёр не предоставит allowlist или формулу, положительный остаток на
неизвестном складе должен давать `availability_unknown`, а автоматическое
добавление в корзину запрещается. В приложении это реализовано через
`SELLABLE_STORE_IDS` и версию правила `AVAILABILITY_RULE_VERSION`. Для live-
режима allowlist по умолчанию пустой. Истёкший снимок получает статус `stale`;
актуальный остаток с `sellable_quantity > 0` получает `available`, а нулевой —
`unavailable`.

## 4. Ошибки и авторизация

Подтверждено:

- без Basic Auth: `401`, JSON `Content-Type`;
- существующий detail: `200`;
- несуществующий `id`: `404`, JSON `Content-Type`;
- API отвечает `application/json; charset=utf-8`.

## 5. Корзина

Страница корзины подтверждена:

```text
https://ekt.kz/personal/cart/
```

Публичная карточка товара содержит `data-action="add2basket"` и ID товара.
В HTML также обнаружен Bitrix-маршрут обновления строки корзины:

```text
/bitrix/components/bitrix/sale.basket.basket.line/ajax.php
```

Это ещё не подтверждённый контракт добавления товара. Не проверялись и не
вызывались mutating-запросы. Не подтверждены:

- HTTP-метод и параметры добавления;
- способ чтения и изменения позиций;
- guest/auth session и перенос cookies;
- CSRF-токен;
- правила единоразового добавления и идемпотентность;
- CORS и разрешённый способ внешнего вызова.

Статус: **блокер для production-сценария корзины**. До предоставления
официального контракта использовать только fixture или явно маркированную
демонстрационную корзину; не выполнять попытки изменения боевой корзины.

## 6. Сертификаты и инструкции

В проверенном detail-ответе и публичной карточке товара `515291` ссылки на
сертификаты, инструкции, паспорта или PDF не обнаружены.

Нужно запросить у партнёра официальный источник документов: поле API, endpoint,
файловое хранилище или правило построения ссылок. Пока источник не подтверждён,
ассистент не должен утверждать, что сертификат существует.

## 7. Что запросить у партнёра

1. Пример товара с непустым `offers` и описание ID варианта.
2. Продающие склады или формулу `sellable_quantity` по городам.
3. Контракт корзины для гостя и авторизованного пользователя, включая cookies,
   CSRF, CORS, методы чтения/изменения и идемпотентность.
4. Источник сертификатов, инструкций и паспортов.
5. Правила единицы продажи, минимальной партии, шага и кратности.
6. Явный признак окончания пагинации либо разрешённый алгоритм остановки по
   повторению ID.
