# EKT.kz — рабочая заметка по кейсу №1

Дата проверки: 2026-09-23  
Назначение: справочник для разработки ИИ-ассистента чата на сайте [ekt.kz](https://ekt.kz/).

## 1. API товаров

Базовый адрес: `https://ekt.kz/api`

Авторизация: HTTP Basic Auth. Учетные данные предоставлены пользователем; пароль не хранить в репозитории, frontend или логах. Использовать секреты окружения/backend-конфигурации.

### Список товаров

```http
GET https://ekt.kz/api/products
GET https://ekt.kz/api/products?page=2
GET https://ekt.kz/api/products?page=N&per_page=M
```

Ответ:

```json
{
  "page": 1,
  "per_page": 20,
  "count": 20,
  "items": [
    {
      "id": 515291,
      "name": "...",
      "article": "...",
      "price": 64920,
      "image": "https://...",
      "url": "https://ekt.kz/catalog/.../",
      "url_api_detail": "https://ekt.kz/api/products/detail?id=515291",
      "offers": []
    }
  ]
}
```

Важно:

- `count` — количество товаров в текущем ответе, не общее число товаров.
- Стандартный `per_page` — 20; параметр `per_page` поддерживается.
- Параметры `search`, `q` и `article` проверены и игнорируются. Полнотекстовый поиск нужно делать в локальном индексе.
- `page=0` возвращает первую страницу.
- Очень большой номер страницы возвращает товары первой страницы, но сохраняет переданный номер в поле `page`. Окончание синхронизации определять по повторению ID/набора товаров, а не только по `page` или `count`.
- Каталог нужно периодически синхронизировать, затем обновлять актуальные цену и остатки через detail-запрос.

### Детальная карточка

```http
GET https://ekt.kz/api/products/detail?id=515291
```

Ответ содержит:

```json
{
  "id": 515291,
  "name": "...",
  "article": "...",
  "description": "...",
  "price": 64920,
  "quantity": 23,
  "stores": [
    {"id": 3, "name": "Шымкент (ул.Байдукова)", "quantity": 2}
  ],
  "image": "https://...",
  "url": "https://ekt.kz/catalog/.../",
  "offers": [],
  "properties": {
    "TORGOVAYA_MARKA": "Legrand"
  }
}
```

Правила обработки:

- `properties` — динамический объект: состав полей зависит от категории.
- `stores` содержит клиентские филиалы и служебные склады (`Брак`, `Маркетинг`, `перемещение`, `Восстановленный продукт` и т. п.). Для ответа о самовывозе фильтровать/помечать служебные склады.
- `quantity` в проверенной карточке совпадает с суммой складских остатков.
- Цена приходит числом; в контексте сайта это тенге, но валюту закрепить конфигурацией.
- Возможны противоречия между названием/описанием и `properties`. Не выдавать спорную характеристику без оговорки, при необходимости ссылаться на карточку или передавать менеджеру.
- `offers` в проверенных товарах пустой; не считать его структуру установленной.

### Ошибки и транспорт

- Без Basic Auth: `401`.
- Отсутствующий `id`: `400`.
- Несуществующий товар: `404`.
- API отвечает JSON с `Content-Type: application/json; charset=utf-8`.
- CORS-заголовок не обнаружен; API вызывать только с backend.
- Basic Auth нельзя помещать в браузерный код.

## 4. Источники знаний ассистента

1. API detail — актуальные товарные данные, цена и остатки.
2. Локальный индекс API списка — поиск по названию, артикулу, бренду и характеристикам.
3. FAQ — типовые технические и клиентские вопросы.
4. Страницы доставки/оплаты/возврата — правила заказа.
5. Контакты — филиалы, адреса, телефоны, email и графики.
6. Карточка/категория сайта — ссылка на первоисточник для пользователя.

Правило приоритета: для цены и наличия использовать свежий API detail; для доставки, оплаты и общих правил — актуальную страницу сайта; при конфликте данных сообщать о необходимости уточнения у менеджера.

## 5. План интеграции

```text
Чат пользователя
  -> backend ассистента
     -> локальный индекс каталога
     -> API ekt.kz для свежей карточки/остатков
     -> база FAQ, доставки, контактов и правил
```

Минимальный функционал ассистента:

- найти товар по естественному описанию или артикулу;
- уточнить недостающие параметры;
- показать несколько подходящих вариантов с ценой, фото и ссылкой;
- проверить наличие по выбранному городу/филиалу;
- сравнить товары и предложить аналог только при подтвержденной совместимости;
- ответить по оплате, доставке, самовывозу и контактам;
- передать менеджеру вопрос, если API не содержит данных или характеристики противоречат друг другу.

Не заявлять возможности оформления заказа, изменения корзины или заказа через эти API: предоставленные endpoints доступны только для чтения товаров.
